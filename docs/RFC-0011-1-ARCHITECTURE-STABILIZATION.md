# RFC-0011.1 — Architecture Stabilization & Executive Contracts

**Status:** APPROVED & IMPLEMENTED  
**Author:** AI Studio Agent / Intent OS Core Team  
**Supercedes:** Hardcoded policy conditionals in ECC / COR  
**Target Version:** v0.4.4-alpha / v3.0 Cognitive Kernel  

---

## 1. Executive Summary

RFC-0011.1 formalizes and stabilizes the executive policy contracts and orchestration capabilities introduced in RFC-0011 (Executive Cognitive Controller) and RFC-0010 (Capability Orchestrator). 

It enforces strict separation between:
1. **ExecutiveQualityPolicy:** Purely cognitive quality thresholds (IQI, PQI, replan limits, dialogue iterations).
2. **ExecutiveExecutionPolicy:** Operational and environmental execution constraints (cost limits, latency, network access, cloud vs. local execution).
3. **ExecutionEnvironment:** Taxonomy and dynamic catalog registration of physical/virtual runtimes (local processes, desktop host, server, cloud, edge, mobile, browser).
4. **ExecutiveDecisionTable:** Declarative, rule-based decision precedence engine replacing procedural hardcoded conditionals.
5. **PolicyProvenance:** Complete provenance tracking identifying the source and authority level of active policies.

---

## 2. Key Architectural Principles

- **Constitution Always Prevails:** Tier 1 rules (Constitution and safety policy) override all execution, quality, or user-level rules.
- **Strict Domain Decoupling:** `CPE` remains agnostic of runtime environments and platform details, specifying only abstract capabilities. `COR` handles environment selection and assignment.
- **Declarative Precedence Tiers:**
  1. `1_CONSTITUTION` (Constitution & Safety Guards)
  2. `2_EXECUTION_POLICY` (Security, Isolation, Offline/Network constraints)
  3. `3_QUALITY_POLICY` (Cognitive Quality Gates: IQI, PQI, Dialogue)
  4. `4_RECOVERY_LIMITS` (Max replans, max reorchestrations, max dialogue)
  5. `5_COST_LATENCY` (Cost and Latency limits)
- **Environment Ranking:** `COR` scores available execution environments based on capability match, network policies, cost, latency, and security tier.

## 3. Data Models and Contracts

### 3.1 Policy Provenance (`PolicyProvenance`)
```python
class PolicyProvenance(str, Enum):
    SYSTEM_DEFAULT = "system_default"
    USER_OVERRIDE = "user_override"
    ENVIRONMENT_POLICY = "environment_policy"
    ENTERPRISE_POLICY = "enterprise_policy"
```

### 3.2 Executive Quality Policy (`ExecutiveQualityPolicy`)
```python
@dataclass
class ExecutiveQualityPolicy:
    profile_id: str = "standard"
    risk_profile: str = "standard"
    min_iqi: float = 0.60
    min_pqi: float = 0.60
    max_planning_iterations: int = 2
    max_replans: int = 2
    max_dialogue_iterations: int = 3
    provenance: PolicyProvenance = PolicyProvenance.SYSTEM_DEFAULT
```

### 3.3 Executive Execution Policy (`ExecutiveExecutionPolicy`)
```python
@dataclass
class ExecutiveExecutionPolicy:
    policy_id: str = "default_execution_policy"
    max_cost: float = 1.0
    max_latency: float = 60.0
    internet_allowed: bool = True
    cloud_execution_allowed: bool = True
    offline_required: bool = False
    allowed_environment_types: List[str] = field(default_factory=list)
    privacy_requirements: str = "standard"
    provenance: PolicyProvenance = PolicyProvenance.SYSTEM_DEFAULT
```

### 3.4 Execution Environment Taxonomy (`ExecutionEnvironmentType`)
```python
class ExecutionEnvironmentType(str, Enum):
    LOCAL_PROCESS = "local_process"
    DESKTOP = "desktop"
    BROWSER = "browser"
    MOBILE = "mobile"
    SERVER = "server"
    CLOUD = "cloud"
    EDGE = "edge"
    REMOTE = "remote"
```

## 4. Execution Graph Node Assignment (`NodeAssignment`)

`NodeAssignment` objects generated by `COR` now include full environment metadata:
- `environment_id`: Unique identifier of selected execution environment (e.g., `env_local_process`, `env_desktop_host`).
- `environment_type`: Category of runtime environment.
- `environment_score`: Quantitative suitability score calculated during orchestration.
- `environment_candidates`: Ranked list of candidate environments evaluated for step assignment.

---

## 5. Decision Precedence Table (`ExecutiveDecisionTable`)

The decision engine evaluates candidate rules sequentially by priority and tier:

| Tier | Priority Range | Name | Description |
|---|---|---|---|
| 1 | 10 - 19 | `1_CONSTITUTION` | Constitutional and core safety policy checks |
| 2 | 20 - 29 | `2_EXECUTION_POLICY` | Network access, offline requirements, environment restrictions |
| 3 | 30 - 39 | `3_QUALITY_POLICY` | IQI, CDM dialogue questions, PQI thresholds |
| 4 | 40 - 49 | `4_RECOVERY_LIMITS` | Max replans, reorchestrations, and dialogue iteration guards |
| 5 | 50 - 59 | `5_COST_LATENCY` | Financial cost and operational latency limits |
